# ForterOS P0 (Trust Command Center, demo mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete ForterCIP Trust Command Center frontend (intro, shell, ⌘K ask-bar with 12 answer cards, chat, order dossiers, pins/saved views, Pulse command center, role lenses) as a new workspace package running entirely on demo fixtures.

**Architecture:** A new Vite + React 18 + TypeScript package `packages/forteros-frontend` inside this pnpm workspace, porting the approved Claude Design mockup (vendored under `design-reference/forteros/`) into typed, tested modules. All data comes from a `demo-data.ts` fixture module behind small provider interfaces so P1 can swap in the live Forter MCP gatekeeper without touching the UI. No backend changes in P0.

**Tech Stack:** pnpm workspace (pnpm 11.17.0), Vite 7, React 18.3, TypeScript 5.9, Vitest + @testing-library/react + jsdom, pure-SVG charts (no chart library).

**Spec:** `docs/superpowers/specs/2026-08-10-forteros-design.md` (approved). This plan implements phase **P0** of §10. Out of scope here (later plans): FeedbackFlow wizard, live MCP gatekeeper, Agents console, Platform (Apps/Connectors/Access), chat guided actions, workerd hosting.

## Global Constraints

- Package name: `@forteros/frontend`; location `packages/forteros-frontend` (auto-included by `pnpm-workspace.yaml` `packages/*`).
- Design tokens (exact): ground `#070B12`; Forter blue `#005DE8`; bright blue `#2A8BFF`; approve/trust green `#00D894`; decline/risk red `#FF6161`; review/warn amber `#FFB547`. Font: Poppins. **No gradients anywhere** (design-system rule).
- Brand renders as **Forter**CIP (bold "Forter", light "CIP"); page title `ForterCIP — Trust Command Center`.
- Demo data values must match `design-reference/forteros/os-core.jsx` exactly (e.g. 7-day approval series ends 96.4; 859 declines across 10 reasons; orders `40E018J` DECLINE / `40E025T` APPROVE).
- All commands run from repo root. Test command: `pnpm --filter @forteros/frontend test`. Dev server: `pnpm --filter @forteros/frontend dev` (port 3100). Build: `pnpm --filter @forteros/frontend build`.
- Commit after every task on branch `forteros-design`. Commit messages: `feat(forteros): …` / `test(forteros): …` / `chore(forteros): …`.
- The design reference files are the visual source of truth. When a porting step says "port X", it means: copy the JSX/CSS from the referenced file, convert to typed TSX (props interfaces, no `window.*` globals, imports instead of `Object.assign(window, …)`), and keep markup/class names/copy text identical.
