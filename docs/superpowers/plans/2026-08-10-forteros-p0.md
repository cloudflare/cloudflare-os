# ForterOS P0 (Trust Command Center blueprint gadget, demo mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the ForterCIP Trust Command Center as a Cloudflare OS **gadget** (Pulse boards, ⌘K ask-bar with 12 answer cards, identity dossiers, pins/saved views, role lenses, disputes panel) running on demo fixtures, packaged as a bundled **format blueprint** instantiable on a local `pnpm run-local` instance.

**Architecture:** A new workspace package `packages/forteros-gadget` holds typed, tested TSX source plus an esbuild step that emits the two gadget files: a single self-contained `client.js` (React + app + injected CSS, prebundled — the gadget sandbox provides no bundler, JSX, or network) and `server.js` (a Durable Object class exposing the data seam as Cap'n Web methods). A Vite dev harness emulates the `gadget` RPC stub for fast local iteration; final QA runs the real platform via `pnpm run-local`, and the gadget is exported as a `.gadget` blueprint and vendored into `format-blueprints/`. Upstream chat/agents/gatekeepers are untouched in P0.

**Tech Stack:** pnpm workspace (pnpm 11.17.0), esbuild, Vite 7 (dev harness), React 18.3, TypeScript 5.9, Vitest + @testing-library/react + jsdom, pure-SVG charts.

**Spec:** `docs/superpowers/specs/2026-08-10-forteros-design.md` (approved, incl. 2026-08-10 platform-extension revision). This plan implements phase **P0** of §10. Later plans: P1 `gatekeeper-forter` + feedback wizard, P2 ROI ledger, P3 branding/distribution, P4 workerd hosting.

## Global Constraints

- Package `@forteros/gadget` at `packages/forteros-gadget` (auto-included by `pnpm-workspace.yaml`).
- **Gadget client runtime rules** (verified against `packages/workshop-backend/src/agent.ts:377-522`, `packages/workshop-frontend/src/GadgetUI.tsx`, `packages/workshop-backend/src/overseer.ts:9038-9062`):
  - The client is exactly **one file, `client.js`**, executed verbatim as a single ES module inside a sandboxed iframe. No JSX/TS at runtime, no relative imports, no bare specifiers → everything must be prebundled into it.
  - CSP blocks all network (`connect-src 'none'`, scripts/styles only via `data:`/inline). CSS must be injected as inline `<style>` by the bundle. No `alert`/`confirm`/`window.open`/`window.print`.
  - `gadget` (RPC stub to the server DO), `RpcTarget`, and `RpcStub` are already in lexical scope — **must not be imported or redeclared** in the emitted bundle. Call the server as `await gadget.method(args)`.
  - Keep the emitted `client.js` under ~1.5 MB (it is `encodeURIComponent`-ed ~3× into a `data:` URL srcdoc with a 20 s load timeout).
- **Gadget server rules:** `server.js` must `export class Gadget extends DurableObject` (import from `"cloudflare:workers"`), no fetch handler, no internet; additional `.js` modules may be imported by `server.js` (all `.js` files load as modules).
- Design tokens (exact): ground `#070B12`; Forter blue `#005DE8`; bright `#2A8BFF`; green `#00D894`; red `#FF6161`; amber `#FFB547`; Poppins; **no gradients**. Brand renders **Forter**CIP.
- Demo data must match `design-reference/forteros/os-core.jsx` exactly (approval series ends 96.4; 859 declines across 10 reasons; orders `40E018J` DECLINE / `40E025T` APPROVE).
- Poppins: the sandbox cannot fetch fonts. The dev harness may use Google Fonts; the gadget bundle falls back to the host stack `Poppins, system-ui, sans-serif` in P0 (font embedding as base64 `@font-face` is a P3 polish item — note it in the gadget README).
- All commands run from repo root. Tests: `pnpm --filter @forteros/gadget test`. Dev harness: `pnpm --filter @forteros/gadget dev` (port 3100). Gadget build: `pnpm --filter @forteros/gadget build` → `packages/forteros-gadget/dist-gadget/{client.js,server.js,README.md}`.
- Commit after every task on branch `forteros-design`. Messages: `feat(forteros): …` / `test(forteros): …` / `chore(forteros): …`.
- Porting steps mean: copy JSX/CSS from the named design-reference file, convert to typed TSX (props interfaces, imports instead of `Object.assign(window, …)`), keep markup/class names/copy text identical.

```js
// Emits the two gadget files. client.js must be ONE self-contained ES module:
// React bundled in, CSS injected at runtime, and the platform-provided globals
// (gadget, RpcTarget, RpcStub) left as free identifiers.
import { build } from "esbuild";
import { mkdir, copyFile, readFile, writeFile } from "node:fs/promises";

await mkdir("dist-gadget", { recursive: true });

const client = await build({
  entryPoints: ["src/client-entry.tsx"],
  bundle: true,
  format: "esm",
  outfile: "dist-gadget/client.js",
  jsx: "automatic",
  // Inline stylesheets: import "./x.css" becomes a string we inject.
  loader: { ".css": "text" },
  define: { "process.env.NODE_ENV": '"production"' },
  minify: true,
  metafile: true,
});

await build({
  entryPoints: ["src/server/server-entry.ts"],
  bundle: true,
  format: "esm",
  outfile: "dist-gadget/server.js",
  external: ["cloudflare:workers"],
  minify: false,
});

await copyFile("src/server/GADGET_README.md", "dist-gadget/README.md").catch(() => {});
const size = (await readFile("dist-gadget/client.js")).byteLength;
if (size > 1.5 * 1024 * 1024) throw new Error(`client.js is ${size} bytes (> 1.5 MB budget)`);
console.log(`client.js ${(size / 1024).toFixed(0)} KiB`);
```
